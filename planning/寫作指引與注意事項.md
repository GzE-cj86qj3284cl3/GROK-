# 寫作指引與注意事項（改寫版）

## 一、驗收定義

- **最低字數**：每章正文至少 8,000 個漢字，以 `scripts/validate_chapters.py` 的實際計數為依據，不得使用 UTF-8 位元組大小替代。
- **狀態分級**：已建立（有檔案）／情節初稿（可讀、有事件線）／文字擴寫中／字數達標／編輯驗收完成。不得跳級或把存在當完成。
- **來源優先**：作者最新明確要求 > 已確認核心世界觀 > 明確採納的補完設定 > 章節已發生且可核實的事件 > 候選假說。
- **保留歷史版本**：本次作者授權大幅改寫舊章；實際套用時仍需先建立Git備份分支或標籤，不在沒有備份的情況下覆蓋。

## 二、敘事與風格

- 全文使用台灣慣用繁體中文，避免錯字、機械重複與不自然轉換詞。
- 第三人稱有限視角，以雪鴨當下感官、認知、選擇為主；不得直接描寫她無法知道的遠方實際情況。
- 主角外在寡言、內心生動，重視實際利益、個人自由與工作專業；不能寫成萬能或無情的機器。
- 允許成人向、陰暗制度與親密題材，但必須服務角色、關係與故事，避免用同樣身體反應取代情節推進。
- 每章應有獨特的行動、阻力、成本、轉折與後果。擴寫不得只是反覆增加天氣、感受、等待描寫。

## 三、證據與正典

- 明確區分**客觀已觀察**、**主角推測**、**作者未定**；所有關鍵祕密必須保留為未解狀態，直到作者指示。
- 雪鴨的出生管理晶片已取下；體內未知晶片仍未解密，兩者不得混淆。
- 不得擅自確定外部識別設備、灰域反光與匿名委託人的身分是否相同。
- 新增大事件與正式角色應同步更新角色、時間線、關係與伏筆。

## 四、逐章工作流程

1. 先讀 `world/00_核心世界觀.md` 及可用的完整世界觀、`memory/目前劇情進度.md`、`planning/時間線.md`。
2. 擬定本章的行動目標、場景清單、至少一項新的事件變化、付出的成本及結尾後果。
3. 完成初稿後計算正文漢字數，未達8,000不得標示完成。
4. 二次編輯：視角、動機、時間軸、錯別字、事件因果、設備和契約限制。
5. 同步 `memory/故事總摘要.md`、`memory/人物狀態.md`、`memory/未回收伏筆.md`、`memory/角色關係.md`、`memory/目前劇情進度.md`、`planning/時間線.md`。
6. 更新 README 和進度驗收報告，檢查提交差異後才推送。
